## 2. Product Overview

**한 줄 설명**: "지난달보다 돈이 덜 남았는데 왜 그런지 모르겠다"는 순간에, 두 달의 숫자를 비교해
이익 변동에 영향을 준 항목을 보여주는 무료 도구.
**서브헤딩(화면)**: "왜 이번 달에 돈이 덜 남았지?"
**SEO Title**: 이익 변동 진단 | 왜 이번 달에 돈이 덜 남았지?

**Problem**: 소상공인은 "이번 달에 돈이 덜 남았다"는 감각은 있어도, 매출·식재료비·인건비·임대료·
수수료·기타비용 중 무엇이 변했는지는 장부 없이 알기 어렵다. 회계 프로그램은 입력 부담이 커서
바쁜 사장님이 매번 쓰기 어렵다.

**Solution**: 지난달·이번 달 6개 항목만 입력하면, 항목별로 이익에 미친 영향을 계산해 영향이 큰
순서로 보여주고, 항목별로 무엇을 먼저 확인하면 좋을지(다음 확인)를 안내한다. 장부 입력을 요구하지
않고, "원인"을 단정하지 않는다.

## 3. Target User

- Primary User: 개인사업자·소상공인 (음식점·주점 우선)
- Secondary User: 매출·비용을 대략적으로만 파악하고 있는 1인 사업자

## 4. User Scenario

```
① 지난달 매출·비용 5+1개 항목 입력
↓
② 이번 달 매출·비용 5+1개 항목 입력
↓
③ 이익 변동(증감) → 상태 → 항목별 영향 순위 확인
↓
④ 영향이 큰 항목부터 "다음 확인" 안내 순서대로 거래내역 점검
```

## 5. Functional Requirements

- 입력값 실시간 콤마 처리 · 실시간 계산(버튼 없이도)
- 지난달·이번 달 이익 계산, 이익 증감 계산
- 항목별 이익 영향 계산 + 영향 순위(절대값 내림차순, 동률 타이브레이크)
- 상태 판정(이익 감소/증가/동일/적자 축소/적자 전환/전부 0) + 결과 문구
- 항목별 신규 발생·미발생 안내(전월 0→이번 달 양수, 전월 양수→이번 달 0)
- 다음 확인(행동 힌트) — 항목별 1차 확인 사항 + 관련 도구 링크
- 원인 확정 불가 캡션 상시 노출
- 입력값 자동 저장(localStorage) / "초기화" 버튼
- 면책 문구 상시 노출 — 세무·회계 자문 아님

## 6. Input Definition

12개 입력(6항목 × 지난달/이번 달), 전부 필수, 기본값 0, ≥0 정수.

| 항목 | 필수 | 단위 | 검증 |
|---|---|---|---|
| 매출 | O | 원(정수) | ≥ 0 |
| 식재료비(또는 상품매입비) | O | 원(정수) | ≥ 0 |
| 인건비 | O | 원(정수) | ≥ 0 |
| 임대료 | O | 원(정수) | ≥ 0 |
| 플랫폼·카드·결제 수수료 | O | 원(정수) | ≥ 0 |
| 기타비용 | O | 원(정수) | ≥ 0 |

쉼표·원화기호는 UI에서 허용, 내부는 정수로 normalize(소수점 반올림). `Number.isSafeInteger`
범위 초과는 에러 처리.

## 7. Non-Functional Requirements

- 서버·API·로그인 없음. 입력값은 localStorage 에만, 전송 없음.
- 외부 라이브러리 신규 도입 금지. 무빌드 정적 구조 유지.
- 모바일(400px)·데스크톱(1280px) 모두 가로 스크롤 없이 렌더.
