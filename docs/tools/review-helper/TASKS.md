# 작업 계획 (TASKS)

각 단계는 **완료 기준을 모두 만족해야** 다음 단계로 넘어갑니다. 한 단계가 끝날 때마다 사용자에게 ① 한 일 ② 확인하는 방법 ③ 다음 단계를 보고하세요.

---

## 0단계. 저장소 파악 (코드 수정 없음)

- [ ] **작업 폴더가 git 저장소인지 확인**한다(`git status`). 저장소가 아니면(ZIP 사본) 여기서 멈추고 사용자에게 알린다. 원격 저장소 주소와 현재 브랜치도 보고한다.
- [ ] Python·Node가 설치되어 있는지 확인한다(`python --version` 또는 `py --version`, `node --version`).
- [ ] 저장소 구조를 훑고 기존 무료도구(`pages/tools/...`)가 어떻게 만들어졌는지 확인한다(HTML 구성, 공통 CSS·헤더·푸터, GA4 코드 위치, 데이터 JSON을 읽는 방식, 배포 방법).
- [ ] 기존 `CLAUDE.md` 유무를 확인한다(있으면 합치기).
- [ ] 도구 페이지 경로는 `pages/tools/review-helper/`로 확정이다. 이 패키지의 `data/review-helper/`를 저장소의 어느 위치에 둘지는 기존 도구가 데이터 JSON을 두는 방식을 보고 **제안**한다(기본 제안: `data/review-helper/`).
- [ ] 기존 도구의 문서 구조(제목, 설명, 광고·분석 코드)를 그대로 따를지 확인한다.

**완료 기준**: 사용자에게 "발견한 구조 / 제안하는 폴더 / 질문(OPEN-ITEMS 중 지금 필요한 것)"을 한 장으로 보고하고 승인을 받는다.

---

## 1단계. 뼈대와 데이터

- [ ] 새 브랜치를 만든다(예: `feature/review-helper`).
- [ ] `data/review-helper/`에 데이터 파일을 둔다. `python data/review-helper/validate.py`가 "통과"인지 확인한다.
- [ ] 도구 페이지 뼈대: `index.html`, `css/`, `js/`(`main.js`, `data.js`)를 만든다. 기존 도구의 공통 레이아웃을 따른다.
- [ ] `DESIGN-TOKENS.md`의 색·글자·간격을 CSS 변수로 옮긴다.
- [ ] JSON 5개(`platforms`, `checklist`, `types`, `templates`, `abuse-words`)를 읽어 오는 모듈과 오류 처리(PRD 5절).
- [ ] 해시 라우터(`#home`, `#paste`, `#capture`, `#confirm`, `#result`, `#reply`, `#report`)와 상태 객체(PRD 7절).
- [ ] `HUB_URL` 같은 설정값은 한 곳(`js/config.js`)에 모은다.

**완료 기준**: 페이지가 열리고, 콘솔 오류 없이 JSON이 읽히며, 해시를 바꾸면 빈 화면이라도 전환된다.

---

## 2단계. 핵심 로직 + 테스트 (화면 없이)

- [ ] `js/abuse.js`: `abuse_check.py`의 규칙을 그대로 옮긴다.
- [ ] `js/classify.js`: `classify_check.py`와 `types.json`의 `classification.steps`를 옮긴다.
- [ ] `js/fill.js`: 템플릿의 `[빈칸]`을 찾고 값으로 채우는 함수, 남은 빈칸 수 계산.
- [ ] `js/policy.js`: 확인일 경과·신뢰도 판단(PRD 6절).
- [ ] `tests/review-helper/`: Node 기본 테스트(`node --test`)로 `abuse-tests.json` 36개, `classify-fixtures.json` 31개를 읽어 모두 검사한다. 빈칸 채우기·확인일 판단 테스트도 추가한다.

**완료 기준**: `node --test tests/review-helper/`가 모두 통과한다. Python 참고 구현과 결과가 다르면 JavaScript가 아니라 **참고 구현을 기준**으로 고친다(참고 구현이 틀렸다고 생각되면 사용자에게 알린다).

---

## 3단계. 모바일 화면 (390px)

`PRD.md` 3절과 `design-reference/`를 보고 순서대로 만든다.

- [ ] 처음 화면(탭·준비중 안내·무료도구 돌아가기)
- [ ] 붙여넣기(지우기, 예시 넣기)
- [ ] 정보 확인(플랫폼·별점·글자 수정·가게 이름)
- [ ] 분석 결과(유형 바꾸기 접이식, 신고 문구, 확인할 점, 정책 카드, 다음 단계, 처음부터 다시하기)
- [ ] 답변 초안(유형 칩 가로 스크롤, 안내 상자, 말투, 미리보기, **빈칸 입력칸**, 복사)
- [ ] 신고 전 체크리스트(근거 표시, 공식 안내 카드)
- [ ] 뒤로가기·처음부터 다시하기가 어디서든 동작한다.

**완료 기준**: PRD 10절의 수용 기준 2·3번이 모바일에서 손으로 확인된다. 텍스트가 잘리거나 화면 밖으로 나가지 않는다.

---

## 4단계. PC 3열 (≥ 960px)

- [ ] 같은 데이터·로직으로 3열 레이아웃(왼쪽 입력 / 가운데 결과·체크리스트 / 오른쪽 답변·공식 안내).
- [ ] 유형을 바꾸면 신고 문구와 답변 초안이 함께 바뀐다.
- [ ] 이미지 붙여넣기(Ctrl+V)·끌어다 놓기 자리(5단계에서 연결).
- [ ] "처음부터 다시하기"가 입력과 선택을 모두 되돌린다.

**완료 기준**: 960~1440px에서 깨지지 않고, 모바일과 같은 입력에 같은 결과가 나온다.

---

## 5단계. 캡쳐 글자 읽기 (보조 기능)

- [ ] Tesseract.js(한국어)를 **캡쳐 화면에 들어갈 때만** 지연 로드한다. 버전을 고정하고 사용한 버전을 사용자에게 알린다.
- [ ] 갤러리 선택, 사진 찍기, PC의 끌어다 놓기·Ctrl+V.
- [ ] 큰 이미지는 줄여서 처리, 진행 표시, 실패·시간 초과 시 붙여넣기로 안내.
- [ ] 인식된 글자를 정보 확인 화면의 리뷰 내용에 채운다(사장님이 수정).
- [ ] 이미지는 어디에도 업로드하지 않는다(네트워크 탭으로 확인).

**완료 기준**: 실제 리뷰 스크린샷 5장 이상으로 시험한 결과(잘 읽힌 정도)를 사용자에게 **솔직하게** 보고한다. 정확도가 낮으면 기능을 막지 말고 "글자가 틀릴 수 있어요" 안내가 눈에 띄는지 확인한다.

---

## 6단계. 분석·설명 콘텐츠·마무리

- [ ] GA4 이벤트(PRD 8절). 이벤트에 리뷰 내용이 들어가지 않는지 확인한다.
- [ ] 하단 "기록·통계" 클릭 이벤트.
- [ ] 도구 아래 정적 HTML: **사용 방법**(3단계), **자주 묻는 질문 5개 이상**(예: 신고하면 바로 삭제되나요? / 별점만 있는 리뷰도 신고되나요? / 이 도구가 신고 대상을 확정해 주나요? / 입력한 리뷰는 저장되나요? / 어느 플랫폼을 지원하나요?). 답은 `platforms.json`·`README`에서 확인된 내용만 쓴다.
- [ ] `<title>`, `<meta name="description">`, 대표 이미지(OG)를 기존 도구 방식으로 설정한다.
- [ ] `HUB_URL`이 정해졌는지 `OPEN-ITEMS.md`로 확인하고 반영한다.

**완료 기준**: 이벤트가 기록되고, 설명 섹션이 모바일에서 읽기 편하다.

---

## 7단계. 점검과 배포 준비

- [ ] `validate.py`, `abuse_check.py`, `classify_check.py`, `node --test` 전부 통과.
- [ ] 수동 점검표:
  - [ ] 모바일(iOS Safari, Android Chrome)과 PC(Chrome, Edge)에서 전체 흐름
  - [ ] 붙여넣기 / 캡쳐 두 경로 모두
  - [ ] 욕설 리뷰에서 "신고대상은 아닙니다"가 나오지 않는다
  - [ ] 도구 자신이 리뷰를 허위·거짓이라고 판정·단정하는 표현이 없을 것
  - [ ] 정책 카드에 시행일·확인일이 보인다
  - [ ] 네트워크 요청에 리뷰 내용이 없다
  - [ ] 키보드만으로 사용할 수 있다
  - [ ] 새로고침하면 입력이 지워진다
- [ ] 변경 파일 목록과 확인한 내용을 사용자에게 요약한다.
- [ ] **배포는 하지 않는다.** 병합·배포 여부는 사용자가 결정한다.

**완료 기준**: 사용자가 요약을 보고 "배포해도 된다"고 승인할 수 있다.
