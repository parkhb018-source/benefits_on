# 리뷰 대응도우미 — 제품 명세 (PRD)

작성일 2026-10-02 · 대상: 1차 버전

## 1. 목표와 범위

**목표**: 배달 사장님이 부정 리뷰를 받았을 때, 감정적으로 대응하기 전에 ① 어떤 유형의 리뷰인지 ② 신고 대상인지(참고) ③ 무엇을 확인해야 하는지 ④ 어떻게 답하면 좋은지를 **1분 안에** 알 수 있게 한다.

**이 도구는 판정하지 않는다.** 실제 주문 내역을 알 수 없으므로 "허위 리뷰"라고 판단하지 않고, 확인할 점과 공식 신고 경로를 안내하는 도구다.

### 1차에 포함
- 리뷰 입력: 붙여넣기(기본), 캡쳐 이미지에서 글자 읽기(보조, 글자가 틀릴 수 있음)
- 유형 15개 자동 분류 + 사장님이 직접 바꾸기
- 신고 대상 여부 안내(참고) + 이유 + 확인해 볼 점
- 유형별 답변 템플릿 45개(15개 유형 × 3가지 말투), 빈칸 채우기, 복사
- 신고 전 체크리스트 + 플랫폼 공식 안내 링크(시행일·확인일 표시)
- 초기화(지우기, 처음부터 다시하기)
- 모바일 우선 + PC 3열

### 1차에서 제외 (만들지 않는다)
- AI(LLM) 분석·생성, 서버 저장, 로그인
- 기록 관리, 통계, 반복 패턴 분석 → 하단 탭에 "준비중"으로만 표시
- 신고문 대필(신고서 문구 생성)
- 혐오·차별 표현 사전
- 네이버 플레이스 리뷰(공식 원문 미확인, `platforms.json`의 `inScope: false`)

## 2. 사용자 흐름

### 모바일 (단계별 화면)

```
처음 화면(0)
 ├─ 리뷰 붙여넣기 → 붙여넣기(1b) ─┐
 └─ 리뷰 캡쳐하기 → 캡쳐(1a) ─────┤
                                  ▼
                       리뷰 정보 확인(2)  ← 플랫폼·별점·글자 수정·가게 이름
                                  ▼
                           분석 결과(3) ──→ 신고 전 체크리스트(5)
                                  ▼
                           답변 초안(4)
```
- 뒤로가기(브라우저·화면 왼쪽 위 화살표)가 동작해야 한다. 화면 전환은 해시(`#paste`, `#confirm` …) 라우팅을 권장한다.
- 3·4번 화면의 "처음부터 다시하기"는 모든 입력과 선택을 지우고 처음 화면으로 간다.

### PC (≥ 960px)
한 화면 3열: **왼쪽 입력 · 가운데 분석 결과+신고 전 체크리스트 · 오른쪽 답변 초안+공식 안내**. 단계 이동 없이 "분석하기"를 누르면 가운데·오른쪽이 채워지고, 유형을 바꾸면 신고 문구와 답변 초안이 함께 바뀐다. 이미지 붙여넣기(Ctrl+V)와 끌어다 놓기를 지원한다.

설정 탭은 없다.

### 1b. 리뷰 붙여넣기 (`Paste`)
- 제목 "받은 리뷰를 붙여넣어 주세요" / 설명 "복사한 글을 붙여넣으면 답변 초안과 확인할 점을 정리해 드려요."
- `리뷰 내용` 라벨 + 오른쪽 **지우기** 버튼(입력창을 비운다). 입력창이 비면 placeholder "여기에 리뷰를 붙여넣어 주세요"와 "예시 리뷰 넣어 보기" 버튼.
- 안내 상자 "스크린샷에서 글자 복사하기": 아이폰 — 스크린샷 속 글자를 길게 눌러 복사 / 갤럭시 — 스크린샷에서 '텍스트 추출'을 눌러 복사.
- 링크 버튼 "복사가 어렵다면 리뷰 캡쳐하기" → 1a
- 파란 큰 버튼 **분석하기** → 2 (입력이 비어 있으면 누를 수 없게 하거나 안내를 보여 준다)
- 예시 리뷰: "배달이 너무 늦게 와서 음식이 다 식었어요. 다시는 안 시킬 것 같아요."

### 1a. 리뷰 캡쳐하기 (`Capture`)
- 어두운 배경(`#0B0E1F`), 왼쪽 위 ×(처음 화면으로), 가운데 제목 "리뷰 캡쳐하기".
- 캡쳐 프레임(흰색 모서리 4개) 안에 올린 이미지 미리보기. 이미지가 없을 때는 안내 문구.
- 아래 컨트롤: 갤러리에서 선택(`<input type=file accept="image/*">`) / 사진 찍기(`capture="environment"`). PC에서는 끌어다 놓기·Ctrl+V 붙여넣기.
- 흰색 시트: 진행 중 "이미지에서 텍스트를 인식하고 있어요..." / "잠시만 기다려 주세요." / "글자가 틀리게 읽힐 수 있어요. 다음 화면에서 꼭 확인하고 고쳐 주세요." / 파란 버튼 **글자 확인하기** → 2 (인식된 글자가 입력된 상태로)
- 인식 실패·시간 초과: 안내 문구와 "붙여넣기로 입력하기" 링크.
- 처리는 브라우저에서만(Tesseract.js, 한국어). 큰 이미지는 줄여서 처리한다. 언어 데이터는 이 화면에 들어갈 때 지연 로드하고, 로딩 중임을 표시한다.

### 2. 리뷰 정보 확인 (`Confirm`)
카드 4개 + 안내 + 버튼.
1. **어느 플랫폼 리뷰인가요?** 칩 4개: 배달의민족 / 쿠팡이츠 / 요기요 / 네이버·기타(2×2). 하나 선택(기본: 배달의민족). 도움말 "직접 골라 주시면 플랫폼별 안내가 정확해져요."
2. **별점** 1~5 선택(선택 입력). 선택하지 않아도 진행 가능.
3. **리뷰 내용**(입력 화면에서 넘어온 글, 수정 가능) + "글자가 잘못 읽혔다면 여기서 고쳐 주세요."
4. **가게 이름 (답변에 들어가요)** 한 줄 입력. 비어 있으면 답변의 `[가게 이름]` 빈칸이 남는다.
5. 초록 안내 "고객 닉네임·전화번호가 보이면 지운 뒤 진행해 주세요."
6. 파란 버튼 **분석하기** → 3
- 플랫폼 이름 칩의 `네이버·기타`는 `platforms.json`의 `naver_place`에 대응한다.

### 3. 분석 결과 (`Result`)
위에서 아래 순서:
1. **요약 카드**(연한 파란): `types.json`의 `result.title` + `pills` + `advice`와 **신고 문구**(`reportStatuses[reportStatus].message`, 굵은 파란색 — `tone`이 `caution`이면 주황 계열 굵은 글씨) + `이유: ` + `result.reason`(비어 있으면 줄 생략) + 카드 맨 아래 `disclaimer`(구분선 위).
   - `advice`와 신고 문구는 **한 문장 흐름**으로 이어서 보여 준다. 예: "이런 유형은 사과와 개선 약속을 담은 답변으로 풀어가는 경우가 많아요. **신고대상은 아닙니다.**"
2. **유형 바꾸기**: 카드 안 파란 글자 버튼 "유형이 맞지 않나요? 바꾸기"(접힘이 기본) → 누르면 유형 칩이 펼쳐진다(시안은 6개, 실제는 15개 전부). 하나를 고르면 접히고 요약·확인할 점·다음 단계가 모두 바뀐다. 분류가 **미분류**이면 처음부터 펼쳐서 "유형을 골라 주세요"를 보여 준다.
3. **확인해 볼 점** 카드(주황 계열): `result.checks` 3개.
4. **관련 플랫폼 정책** 카드: 선택한 플랫폼의 이름, `리뷰운영정책 · {effectiveDate} 시행`, "자세히 보기"(→ 5). (규칙은 6절)
5. **다음 단계** 카드: ① 답변 초안 만들기 → 4 ② `result.step2.title`/`desc` → 5 (`step2`가 null이면 생략)
6. 파란 버튼 **답변 초안 만들기** → 4, 그 아래 보조 버튼 **처음부터 다시하기**, 맨 아래 `disclaimer`
- 대표 유형이 T12가 아니고(예: T06) 욕설이 감지됐으면 요약 카드에 "욕설·비방 표현도 감지됐어요. 신고 전 체크리스트를 확인하세요." 한 줄을 덧붙인다.

### 4. 답변 초안 (`Reply`)
1. **리뷰 유형** 칩 15개 — **옆으로 넘기는** 한 줄 목록(`types.json`의 `shortLabel`), 오른쪽 위 "옆으로 넘겨 보세요". 3번 화면에서 정해진 유형이 선택된 채로 시작한다.
2. **안내 상자**: `types[].replyBanner`. `caution: true`이면 주황 계열, 아니면 연한 파란.
3. **답변 스타일** 3칩: 정중하게 / 간결하게 / 진정성 있게 (`templates.json`의 `polite`/`short`/`sincere`).
4. **답변 미리보기**: 템플릿 본문. `[대괄호]` 빈칸은 **노란색**(`#FFF1C2`)으로 강조하고 오른쪽 위에 "빈칸 N곳".
5. 안내 "노란 칸은 가게 상황에 맞게 직접 채워 주세요. 사실과 다른 사과나 고객을 탓하는 표현은 피하는 게 좋아요."
6. 파란 버튼 **답변문 복사하기**(복사 직후 "복사했어요"로 바뀜) + 보조 버튼 **처음부터 다시하기** + "복사한 뒤 각 플랫폼 사장님 앱의 답글 칸에 붙여넣으세요."

**빈칸 입력(시안에는 없음, 구현 시 추가)**: 시안은 빈칸을 노랗게 보여 주기만 한다. 실제 앱은 미리보기 아래에 **빈칸별 입력칸**을 둔다.
- 입력칸 라벨과 도움말은 `templates.json`의 `blanks[].name`/`meaning`, 입력 예시는 `example`을 placeholder로 쓴다(예시는 가상의 값).
- 입력하면 미리보기가 **즉시** 바뀐다. 채운 값은 노랗게 강조하지 않고, 남은 빈칸만 노랗게 둔다.
- `[가게 이름]`은 2번 화면의 가게 이름으로 자동 채운다(`autoFill: "shopNameInput"`).
- 복사는 빈칸이 남아 있어도 가능하지만, 남은 빈칸이 있으면 복사 버튼 위에 "빈칸 N곳이 비어 있어요" 경고를 보여 준다.
- 유형·말투를 바꿔도 이미 입력한 빈칸 값은 같은 이름의 빈칸에 **유지**한다.

### 5. 신고 전 체크리스트 (`Report`)
- 안내 "게시중단 요청은 명예훼손·개인정보 노출 같은 권리 침해를 직접 설명해야 접수돼요. 아래를 먼저 확인해 보세요."
- `checklist.json`의 문항 8개를 체크박스 행으로(체크 상태는 화면 안에서만 유지). 선택한 플랫폼의 `basis`가 있으면 문항 아래에 작은 글씨로 `근거: {ref}`를 보여 주고, `verified: false`이거나 근거가 없으면 "공식 원문으로 확인되지 않은 항목이에요"를 붙인다.
- 주황 팁 상자: "문제가 되는 문구를 따로 적어 두면 요청서를 쓸 때 도움이 돼요."
- **공식 안내 바로가기**: 플랫폼별 카드(이름, `{title} · {effectiveDate} 시행 · 확인일 {verifiedDate}`) + `officialUrl`이 있으면 "열기"(새 탭), 없으면 `officialUrlNote`.

## 4. 분류 로직

- 규칙 원본: `data/review-helper/types.json`의 `classification.steps`와 `types[].match`.
- 참고 구현: `classify_check.py`(분류), `abuse_check.py`(욕설·모욕 사전).
- 시험: `classify-fixtures.json` 31개, `abuse-tests.json` 36개 — **JavaScript 구현도 모두 같은 결과**여야 한다.
- 입력: 리뷰 글, 별점(선택). 출력: `main`(대표 유형 ID 또는 null), `secondary`(보조 유형), `abusive`, `vulgar`.
- 욕설 사전 규칙은 `abuse-words.json`의 `matchingRules`(9개)를 그대로 따른다. 욕설 단어는 화면에 다시 출력하지 않는다.
- `vulgar`가 true이면 요약 카드의 태그(pills)에 "거친 표현"을 추가한다.
- 보조 유형은 화면에 "함께 감지된 유형: …"으로 작게 보여 줘도 된다(필수 아님).

## 5. 데이터 읽기와 오류 처리

- 화면이 열릴 때 JSON 4개(`platforms`, `checklist`, `types`, `templates`)와 `abuse-words.json`을 한 번에 읽어 메모리에 둔다.
- 읽기에 실패하면(오프라인 등) "정보를 불러오지 못했어요. 새로고침해 주세요."를 보여 주고, 입력 화면은 막지 않는다.
- JSON의 `schemaVersion`이 예상과 다르면 콘솔에 경고한다.

## 6. 플랫폼 정책 표시 규칙

| 상황 | 표시 |
|---|---|
| 기본 | `{policy.title} · {effectiveDate} 시행 · 확인일 {verifiedDate}` |
| `officialUrl` 있음 | "열기" 링크(새 탭, `rel="noopener noreferrer"`) |
| `officialUrl` 없음(배민) | `officialUrlNote` 문구 |
| `confidence`가 `low`이거나 `verifiedDate`가 없음 | "아직 확인 중인 정보예요. 공식 안내를 꼭 확인하세요." |
| 오늘 − `verifiedDate` > `staleAfterDays` | "정책이 바뀌었을 수 있어요. 공식 안내를 확인하세요." |
| `inScope: false`(네이버) 선택 | 위 "확인 중" 문구 + 체크리스트의 근거 없음 표시 |

## 7. 초기화와 상태

- 상태는 메모리 객체 하나(`state`)로 관리한다: `platform`, `rating`, `text`, `shopName`, `type`(대표), `manualType`, `tone`, `blanks`, `checks`.
- **지우기**(붙여넣기 화면): `text`만 비운다.
- **처음부터 다시하기**(3·4번 화면, PC): 모든 상태를 처음 값으로 되돌리고 처음 화면으로(PC는 입력 상태로) 돌아간다. 확인 대화상자는 쓰지 않는다.
- 새로고침하면 모든 입력이 사라진다. 이것은 의도된 동작이다.

## 8. 분석 이벤트 (GA4)

사이트에 이미 있는 GA4 설정을 재사용한다. **아래 이름과 값만** 쓴다. 리뷰 글·가게 이름·빈칸 값은 어떤 이벤트에도 넣지 않는다.

## 9. 비기능 요구

- **성능**: 처음 화면 로딩에 Tesseract를 불러오지 않는다. 입력~결과까지 분석은 즉시(100ms 이내).
- **브라우저**: 최근 2개 버전의 Chrome·Safari(iOS 포함)·Samsung Internet·Edge.
- **접근성**: 키보드만으로 모든 기능 사용 가능, 포커스 표시, 칩에는 `aria-pressed`, 접힘 버튼에는 `aria-expanded`, 안내 문구에는 `role="status"`.
- **개인정보**: `CLAUDE.md`의 원칙을 따른다.
- **SEO·콘텐츠**: 도구 아래에 정적 HTML로 "사용 방법"과 "자주 묻는 질문"(5개 이상), `<title>`·`<meta description>`을 둔다. 광고 심사를 고려해 도구 화면만 있는 얇은 페이지가 되지 않게 한다. (`TASKS.md` 6단계)

## 10. 전체 수용 기준

1. `validate.py`, `abuse_check.py`, `classify_check.py`, JavaScript 테스트가 모두 통과한다.
2. 아래 리뷰를 붙여넣고 "분석하기"를 누르면 대표 유형이 다음과 같다(별점은 괄호).
   - "배달이 너무 늦게 와서 음식이 다 식었어요. 다시는 안 시킬 것 같아요."(2) → 배달 지연
   - "음식에서 머리카락이 나왔어요."(1) → 이물질·위생, 주황 안내
   - "씨발 배달이 한 시간이나 걸리네"(1) → 욕설·비방, "신고 검토가 가능할 수 있어요."
   - "맛있어요 최고예요 또 시킬게요"(5) → 칭찬 감사
3. 어떤 유형에서도 "신고대상은 아닙니다."가 욕설 감지 상태에서는 나오지 않는다.
4. 모바일(390px)과 PC(1280px)에서 레이아웃이 깨지지 않는다.
5. 네트워크 탭에서 확인했을 때 리뷰 내용이 어떤 요청에도 실리지 않는다.
6. 기록·통계 탭을 누르면 안내가 뜨고 GA4 이벤트가 기록된다.
